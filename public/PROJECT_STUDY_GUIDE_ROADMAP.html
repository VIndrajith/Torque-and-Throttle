1. Project Overview & Core Mission

Torque & Throttle is a high-performance, full-stack automotive boutique platform and enterprise management system. It combines an ultra-luxury supercar showroom experience on the client side with a robust dealer inventory engine, real-time telemetry inspection, customer lead pipeline, and dual-database sync architecture (Firebase Firestore + PostgreSQL Cloud SQL / Supabase).

Key Capabilities at a Glance:
  • Client Showroom: Interactive vault catalog, multi-criteria filtering, dyno torque curves, inspection point breakdowns, test drive scheduling, and bespoke model sourcing.
  • Admin Vault Management: Protected administrative portal with Role-Based Access Control (RBAC), live inventory CRUD, drag-and-drop image compression, and status tracking.
  • Lead & Webhook Pipeline: Real-time lead capture dispatched across email, SMS/WhatsApp notifications, and external Make.com AI agent automation webhooks with automatic retries.
  • Dual Persistence: Seamless offline-ready Firestore cache with real-time listeners paired with PostgreSQL Cloud SQL & optional Supabase storage sync.

3. Deep Dive into Core Subsystems

A. Client-Side Routing & Vault Display

The application employs a deterministic hash and pathname resolver in src/App.tsx supporting paths like /#/inventory, /#/admin, and /#/vehicle/:id. This guarantees zero 404s when running in embedded iFrames or single-page host environments.

B. Telemetry & Inspection Engine

Vehicles in Torque & Throttle are not just photo cards; they contain comprehensive engineering telemetry:

  • Dyno Telemetry: RPM vs. BHP & Torque curve coordinates, ECU flash counter, boost pressure (PSI), ambient temperature, and dyno correction factors.
  • Multi-Point Inspection: Paint panel depth readings (Microns) distinguishing Factory, Blend, and PPF; brake pad thickness, tire tread depths, and cylinder compression PSI.

C. High-Reliability Lead Pipeline & Webhooks

When a customer books a test drive or submits an enquiry:

  1. The form payload is validated and normalized in src/utils/mailDispatcher.ts.
  2. It sends data to the server backend (/api/enquiries) to persist in database storage.
  3. The backend relays the lead to external AI Agent automation (Make.com webhook) with a dual-attempt retry policy and safety timeouts.
  4. Instant visual confirmation and tracking reference IDs are provided to the user.

D. Image Optimization & Storage

To prevent bandwidth bloat and maintain blazing load times, src/utils/imageCompressor.ts uses HTML5 Canvas to automatically compress uploaded photos on the client before transmitting to cloud storage or base64 database representations.

Focus: Understand the API design, security, and webhook relays.

  • Examine server.ts: observe how Vite middleware is mounted in development vs. static serving in production.

Phase 3: Database & Drizzle ORM (Day 3)
